Query layer deterministic

search() filters and ranks — score is stars adjusted for review volume, so 4.5★/800 reviews beats 5.0★/3 reviews. explain() returns structured reasons per pick. estimate_cost() maps the price band to a labeled per-person range.

Stateless: no session store. Every result is reproducible from the filters alone.

Agent LLM

Turns "cheap sushi open late" into structured filters — {cuisines:[sushi], price_max:2, open_late:true, city:"Philadelphia"} — calls the query layer, then renders picks and explanations as prose. Holds conversation state: the current shortlist and applied filters.

Demo UI chat

The conversation is the interface: recommendations with explanations, adapted to new constraints mid-demo, plus the drafted invitation. Zero UI build — the 3-minute demo budget goes to the assistant, not pixels.

↻ The constraint loop

  1. User adds a constraint ("somewhere with outdoor seating")
  2. Agent appends flags:[outdoor_seating] and re-queries
  3. Agent diffs the shortlist and explains what changed

✉ The invitation branch

  1. User asks for an invitation
  2. Agent takes the top pick + estimate_cost()
  3. Agent drafts restaurant, time, and estimated cost

KEY DESIGN DECISIONS

  • LLM parses, code retrieves. The demo can't hallucinate a restaurant — every pick comes from search(), never from the model's imagination.
  • Explanation is a function. The "why" behind each pick is generated deterministically, so the demo requirement is met every run, not just when the model feels like it.
  • Stateless data layer. A new constraint is just a re-query with modified filters — no session store to build or debug.
  • Chat is the UI. Shipping pixels would compete with the assistant for the same demo hours.

TRADE-OFFS

  • In-memory module: fastest to build, demo-proof, zero infra. Chosen for the hackathon.
  • Docker + FastAPI: a real service, reproducible, no cloud risk. Stretch goal once the core works.
  • Supabase: the "real integration" story, but needs network + setup time. Skipped for demo reliability.
  • Unknown prices excluded when a budget filter is set — every "cheap" pick is verified cheap, at the cost of ~10k rows.
